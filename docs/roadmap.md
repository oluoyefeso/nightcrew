# NightCrew product status

NightCrew helps people set a goal, delegate execution and judge the result through evidence. The open-source local edition is the core product. Managed mode remains **Coming soon**.

## Available in the local edition

- Daily history and evidence on Home, goal creation one click away, and a compact link to unresolved work across days. Work overview and other operational destinations remain available through More and search.
- Goal workspaces with durable coordination from a single Start goal action, inline questions, prerequisite handoffs, independent goal review and combined checks. Task and crew tuning are available on demand.
- Goal creation starts with an outcome and remembers the selected project. Success criteria, budget and deadline are optional; Save for later keeps a goal without starting it. Goal editing, limit holds and missing project checks can be addressed in the goal workspace.
- Cross-day decisions, task scopes, repository authority and independent reviews.
- Missions, prerequisites, priorities, token limits and saved execution stop times.
- Checkpoint recovery, bounded retries and usage measurements that retain partial or unknown accounting.
- Human-attested objective acceptance with combined repository checks.
- Opt-in check → deploy → release commands, persistent operation results and attention handling.
- Saved model connections, model discovery, bounded synthetic tool checks and explicit connection selection for planning, execution and review.

## Current limits

The automatic conductor coordinates one project per goal. It prepares and runs a bounded plan, verifies combined changes, and allows one correction after goal verification. Questions, missing permissions, unusable plans, exhausted limits and unresolved evidence stop progress visibly. Ready for your review does not authorize merge or deployment. Records identify the exact criteria, checks and revisions assessed; changed work invalidates the result.

The local runner uses Claude Code or an explicitly selected compatible model connection. Repository authority, task limits and crew budgets govern execution. Planning and goal review share admission accounting with task execution. Usage reports reflect observed provider accounting and can be incomplete after interruption; retained reservations are conservative and token thresholds are not guaranteed billing ceilings.

Connection selection does not raise repository authority or resume a paused crew. Direct execution requires tool support and reported token usage; unreported provider cost stays unknown. Model competence and compatibility vary. Explicit synthetic connection checks may use provider tokens separately from task and mission budgets.
